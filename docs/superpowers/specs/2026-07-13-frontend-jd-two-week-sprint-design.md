# 前端 JD 两周冲刺学习手册设计

## 1. 目标与边界

面向掌握 HTML、CSS、JavaScript 基础但不熟悉 React 的学习者，在 14 天、每天 4～6 小时的投入下，建立与目标 JD 对应的前端能力体系。

完成后，学习者应当能够：

- 使用 React、TypeScript、Vite、Zustand 和 Axios 独立完成一个中后台项目。
- 解释 JavaScript、浏览器、网络、React、状态管理、工程化与性能优化的高频原理。
- 完成常见手写题，并能定位典型前端问题。
- 使用结构化表达讲解项目、技术选型、性能优化和故障排查经历。

本手册不承诺用两周替代两年真实工作经验，也不追求覆盖所有前端知识。重点是形成可运行、可解释、可验收的核心能力。

## 2. 学习方式

采用“主线项目驱动 + 高频知识补齐”的方式。所有知识围绕同一个 React 中后台项目逐步落地，避免将原理、编码和面试准备割裂。

每日固定结构：

1. 今日目标与前置知识。
2. 核心概念精讲。
3. 最小代码示例。
4. 必须手写的练习。
5. 主线项目任务。
6. 高频面试题与回答要点。
7. 当日验收与错题复盘。

每个知识点采用四级验收：

- L1 理解：能用自己的话解释。
- L2 编码：脱离教程独立实现。
- L3 排错：能定位常见错误并说明原因。
- L4 表达：能结合项目回答面试追问。

## 3. 知识依赖图

学习顺序遵循以下依赖关系：

```text
HTML/CSS/JavaScript
        │
        ├── 浏览器执行机制 ── 性能优化
        ├── 异步与网络 ────── Axios/RESTful API
        └── 模块化与函数式思想
                    │
                 React 核心
                    │
        ┌───────────┼───────────┐
     Hooks       组件设计      状态管理
        └───────────┼───────────┘
                    │
             工程化与综合项目
                    │
             项目表达与模拟面试
```

## 4. 十四天课程结构

### 第一阶段：JavaScript 与浏览器基础

- 第 1 天：现代 JavaScript、作用域、闭包、`this`、原型与模块化。
- 第 2 天：数组与对象、不可变更新、常用数据结构、常见手写题。
- 第 3 天：事件循环、Promise、async/await、异常处理、浏览器渲染。
- 第 4 天：HTTP、缓存、跨域、RESTful API、Axios 请求层设计。

### 第二阶段：React 核心与状态管理

- 第 5 天：React 心智模型、JSX、组件、Props、State、事件系统。
- 第 6 天：渲染流程、虚拟 DOM、Diff、生命周期与 `useEffect`。
- 第 7 天：Hooks、闭包陷阱、自定义 Hook、表单与副作用管理。
- 第 8 天：组件拆分、组合、受控组件、复用、Context 与路由。
- 第 9 天：状态分类、Zustand、Redux 思想、服务端状态与本地状态。

### 第三阶段：工程化、性能与综合应用

- 第 10 天：Vite/Webpack、模块解析、构建流程、环境变量与代码分割。
- 第 11 天：React 性能、浏览器指标、懒加载、缓存、性能测量与优化。
- 第 12 天：项目整合、登录鉴权、权限、列表筛选、详情编辑与错误边界。
- 第 13 天：测试、调试、线上问题排查、项目复盘与简历表达。
- 第 14 天：综合验收、模拟面试、薄弱项补强和后续学习路线。

## 5. 主线项目

项目为“内容管理与审核后台”，技术栈采用 React、TypeScript、Vite、React Router、Zustand 和 Axios。

核心功能：

- 登录、令牌保存、退出和路由保护。
- 内容列表、分页、搜索、筛选和排序。
- 内容详情、创建、编辑和表单校验。
- 用户角色与按钮级权限。
- 统一请求封装、加载状态、错误提示和取消重复请求。
- Zustand 全局状态与局部状态的合理划分。
- 路由懒加载、组件性能优化和构建产物分析。
- 至少一组组件测试或逻辑单元测试。

项目不依赖真实后端，可通过 Mock API 完成。重点是前端架构、业务流和工程质量，而非视觉复杂度。

## 6. 资料内容标准

完整学习手册需要做到：

- 术语首次出现时使用通俗语言解释。
- 每个原理至少包含一个正确示例和一个常见错误示例。
- 示例能够直接运行，避免只有伪代码。
- 面试答案提供回答结构和追问方向，不提供机械背诵稿。
- 练习题给出提示、参考答案和自测标准。
- 外部资料优先选择 MDN、React、Vite、TypeScript 等官方文档。
- 对两周内无法深入的内容明确标为“了解”或“后续学习”。

## 7. 最终交付物

1. 一份按天组织的完整 Markdown 学习手册。
2. 一份 JD 知识点到课程日期的映射表。
3. 一份每日打卡与四级能力验收表。
4. 一套高频面试题与项目追问题库。
5. 一份主线项目任务清单和完成标准。
6. 一份第 14 天综合模拟面试卷。

## 8. 完成判定

两周冲刺完成不能只以“看完资料”为标准。学习者需要满足：

- 主线项目核心流程可以运行并能现场修改功能。
- 80% 的每日必做练习能在不看答案的情况下完成。
- JD 中每一项技术要求都有对应作品、代码或口头解释作为证据。
- 综合模拟面试的基础题正确率达到 80%。
- 能在 5 分钟内完整讲解项目，并回答技术选型、状态设计、性能优化和问题排查的追问。

## 9. 风险控制

- 如果 JavaScript 基础练习连续两天低于 60%，减少工程化扩展内容，优先补异步、闭包和对象更新。
- 如果每天投入不足 4 小时，保留必做内容，删除标记为“进阶”的任务。
- 如果 React 项目无法在第 9 天前形成完整数据流，第 10 天暂停新增知识，先完成项目闭环。
- 不把背诵面试答案视为掌握；所有核心知识必须至少通过编码或排错验证一次。
